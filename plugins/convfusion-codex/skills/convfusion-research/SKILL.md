# ConvFusion Research

Treat Codex as the agent runtime and ConvFusion as the research operating layer. Use Codex's native tools for browsing, coding, experiments, documents, and execution. Use the bundled ConvFusion MCP tools for durable research assets and lifecycle invariants.

## Start every use safely

1. Resolve the current Codex task working directory as an absolute path. This is the `workspace_root` passed to every ConvFusion MCP tool. Never pass the plugin installation/cache directory.
2. Call `research_workspace` with `action: status` before choosing a workflow. This is read-only and distinguishes an existing research project from an ordinary folder.
3. Only call `research_workspace` with `action: init` when the user explicitly asks to start, create, or initialize a research project. Initialization writes under `<workspace_root>/workspace/` for a new project.
4. If the folder is not a research workspace and the user did not ask to initialize one, continue read-only or explain what initialization would create.

## Select methods progressively

Read only the method files relevant to the current task. The library is under `references/`:

- problem framing and domain understanding: `references/research-understanding/`
- literature search, screening, landscape, and review: `references/literature/`
- hypotheses, novelty, ideas, and contributions: `references/innovation/`
- method design: `references/methodology/`
- experiment, dataset, baseline, ablation, evaluation, and reproducibility: `references/experiment/`
- evidence assessment and result analysis: `references/analysis/`
- direction, risk, feasibility, venue, and go/no-go decisions: `references/research-decision/`
- planning, resources, infrastructure, and progress: `references/research-management/`
- paper, patent, report, presentation, equations, figures, and submission: `references/academic-writing/`

Read the selected method file completely before using it. Combine multiple methods only when the request genuinely spans them; do not load the entire library into context.

## Preserve research invariants

- Evidence is a traceable research fact, not a pasted command output. Keep raw artifacts and record paths, parameters, source, retrieval date, or citation as applicable.
- Claims derive their status from evidence. Use `research_claim` reconciliation instead of asserting that a claim is verified from intuition.
- Supersede evidence; do not erase history. Contradicting evidence is a first-class result.
- Record consequential choices with `research_decision`, including reasons, alternatives, and evidence when available.
- Research State is not a chat summary or workflow stage. The agent may create a state proposal, but must not silently apply it. Leave the proposal for explicit user review.
- A Plan is a research-specific execution blueprint, not a workflow engine. Create it as `draft` unless the user explicitly chooses an auto-execute policy. Do not mark it reviewed or ready without actual review/approval.
- Paper changes generated by the agent remain revision proposals until the user accepts or edits them. Preserve versions and provenance.
- Outputs such as patents, reports, and slides transform research knowledge; they do not mutate Research State.

## Execute and verify

Use native Codex capabilities to perform the research work described by the chosen method or approved Plan. Then:

1. Inspect real outputs, logs, measurements, source pages, or rendered artifacts.
2. Extract candidate findings into concise Evidence records with raw-artifact references.
3. Link Evidence to Claims and reconcile affected Claims.
4. Record decisions that changed the research direction.
5. Propose Research State or paper updates when warranted; do not bypass user review.
6. Re-run `research_workspace status` and report what changed, what remains uncertain, and the next evidence-bearing action.

## Tool routing

- `research_workspace`: initialize or inspect the project.
- `research_project`: inspect or deliberately evolve the adopted topic.
- `research_plan`: create and validate Plan lifecycle transitions.
- `research_evidence`, `research_claim`, `research_decision`: maintain the traceable asset graph.
- `research_state_read`, `research_state_propose`: read state and create reviewable proposals.
- `research_paper`: create papers, inspect gaps/maturity, and propose revisions.
- `research_output`: create and audit patents, reports, and presentations.
- `research_literature_search`, `research_paper_download`: reproducible OpenAlex discovery and local full-text acquisition.
- `research_paper_latex`: compose, validate, compile, and deterministically repair LaTeX artifacts.

For exact workspace and host-migration boundaries, read `assets/codex-adapter.md`.
